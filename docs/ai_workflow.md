# Claude 编写 → Codex 最终审查

## 执行要求

1. 每轮以 `docs/current_task.md` 为范围与验收依据。开始前阅读适用的仓库规范，检查当前分支、最新提交和工作区差异；不覆盖已有修改。
2. 每轮使用一个独立分支。已经在本轮分支上就继续使用；存在未提交修改时一并保留，不 reset、不强制 checkout。
3. 同一时间只有一个工具修改仓库。Claude 更新交接记录并停止后，Codex 才开始。
4. Claude 负责实现、测试和文档；Codex 独立核实并直接修复本轮问题。超出范围的问题记录为下一轮事项，不擅自扩大改动。
5. 验证记录必须包含实际命令、运行环境、结果及未执行项目。已有输出不能当作本轮重新执行的证据。
6. 所有数据对比注明基线；区分真实交易数据与模拟库存结果。不得为了通过测试而削弱断言或隐藏警告。
7. 不在交接文件中记录密钥、凭据或原始客户明细。清理文件之前确认用途；忽略的缓存无需处理。
8. 未获得用户明确授权，不 commit、不 push、不合并。完成后报告最终差异、验证结果与剩余限制，由用户决定提交。


用户审阅验收结果并授权后，检查暂存差异，只提交本轮相关文件。不要直接 `git add .` 混入无关文件。提交之后记录提交号；push 需符合用户的明确授权。
