## 3. 报告解释：R1，优先完成

- **MA-05**：写明模型按每 SKU 补货事件处理 £25、无供应商合单；单位成本是模拟数。记录参数值、单位、使用公式、来源状态（演示/待校准）、责任人/校准日期（无数据时写未定，不臆造）。

## 4. 测试补充：T1，需求—分类—模拟接口

### 推荐方案

增加小型确定性月度销量 fixture，覆盖 0/1/2/3 个月观测；由 `full_months` / `build_sku_profile` / `classify_skus` 的真实输出进入 `simulate`，不手写跳过中间步骤的模拟输入。

- 仅截断月销售：全期 totals 保留，面板无完整月，需求/SS/ROP/EOQ=0；验证 `no_full_month_sales`、零月占比 NaN 的衔接。
- 只有一个完整月：按当前合同 std/CV=0 且 short_history=True；这锁定工程行为，并在测试名称/注释中说明统计未可估，不宣称稳定需求。
- 2→3 月边界：short_history 从 True 变 False；用非退化手算数据验证样本标准差而非仅重复代码。
- 高收入短历史仍 Priority；高周转短历史不能 Stable（现有断言可复用，避免重复镜像测试）。
- 零需求的库存为 0 / 大于 0 分别验证 Normal / Overstock Risk；可在配置副本固定 no_demand_units 区间实现确定性，不更改 live 参数。

可选增加真实 90214U 的输入到输出 smoke check，注明数据集专属；不锁死“库存必须为 11”或把真实数据文件缺失视为业务错误。优先合成 fixture，避免依赖 Excel 才能验证接口。

**取舍**：小样本测试易读、快、能定位接口断裂；真实数据 smoke 提供接线证据但更依赖数据版本。两者不替代真实服务水平验证。

**验收**：在临时副本中通过；分别变异首销前补零、截断月加入统计、单月 NaN 未处理、`<3` 改为 `<=3` 时，对应测试能失败。变异只能在临时副本进行。全库 `python -m pytest -W error -ra` 通过并披露跳过情况，正式输出不变。

## 5. 测试补充：T2，EOQ/阈值边界与稳定不变量

### 推荐方案

保留现有手算和 3,000 SKU fixture 覆盖，补现有空隙：

- 无 cap、零需求、零成本现有合同；EOQ 与**整数化 cap** 相等时不 capped，超过时 capped；覆盖最小 1 件、非整数天数×需求的舍入边界。
- 在其他输入固定时，提高 S 不应降低 Q，提高 h 或 c 不应提高 Q，放宽 cap 不应降低 Q；考虑向上取整可能保持相等，不要求严格变化。
- 固定当前库存的阈值实验：ROP/SS/I 不变、Q/T 不减、stockout 集合不变、不会新增 overstock；同时手算一个超储转 Normal 的 fixture。
- 完整 policy_band 实验：p 和其他随机抽样不变，ROP/SS 与 cap 无关，但 I 可以随 Q 变化；用小样本明确展示与固定库存实验不同的结果，不对总体超储数施加错误单调约束。
- 库存恰等于 ROP、max_stock_level、覆盖门槛及门槛两侧的严格比较；缺货优先级、超储有效阈值两分支的切换。
- 推荐补货使用 max(Q, shortfall)，不能把对 Q 的 cap 误施加到补货缺口上。

**取舍**：这些不变量对合法参数范围成立，比“当前 capped≈59%”更能捕获公式错误且不阻碍合理校准。当前 capped 数量、MA-04 转移数只用于标明输入/配置版本的诊断快照，不作为跨配置通用断言。

**验收**：临时变异 `>` 为 `>=`、误删 cap、将固定库存实验误写成完整重生成等能被相应测试发现；不同合法参数仍满足合同。全库严格测试通过，既有 D1/D3 兼容性测试保留。新增测试数量不是验收目标。

## 6. 诊断工具：E1，可复现的 A/B 和单因素敏感性报告

### 推荐方案

下一轮将本次临时实验整理为独立脚本，显式接收输入 profile、配置路径和输出目录，默认临时目录或要求指定，不覆盖 live。每个场景从基线深拷贝，禁止前一场景累计污染下一场景。

报告应包含：

- 代码提交、输入/配置 SHA-256、依赖版本、seed、SKU 集合/顺序、实验模式（固定库存 / 完整重生成）、实际变更值及舍入/截断规则。
- I/Q/ROP/SS/T 变化数，风险转移矩阵、缺货件数、补货件数、金额、capped 数量/比例、分类及策略变化；绝对值、绝对差、相对同一基线的百分比。
- 所有影响货币口径的逐 SKU 舍入步骤。总额较小时避免仅用相对容差；离散标签/数量精确检查，货币到分；浮点中间量可用注明理由的 `rtol=1e-12, atol=1e-9`。
- 状态金额与真实最优性明确分开；None cap 是反事实分析，不是推荐政策。

可选追加等幅局部扰动、需求均值/波动分别变化、更多种子或联合设计；先定义回答的问题和范围，再做试验，不借此自动寻找或写回“最佳参数”。若要比较参数影响排序，需要预先定义输出指标、参数范围与标准化方式，并报告非线性/交互局限。

**验收**：固定基线 50ce335 下独立复现 review 的 A/B 和九场景，A 不变库存、B 保留随机抽样；相同输入重跑一致；临时配置变化不写正式目录；基线金额和正式报告到分一致。数据/参数版本改变时报告差异及来源，不把变化自动判成错误。

## 7. 业务参数校准：B1，先确定事件口径再估数值

### 待收集与核实

| 参数 / 结构 | 需要的业务依据 | 取舍 |
| --- | --- | --- |
| ordering_cost_gbp | 每次采购单、每次供应商到货还是每 SKU 行/批次的固定处理成本；合单的公共成本与增量成本 | 独立 SKU 模型简单，但供应商合单可能需要成本分摊或联合订货模型，不能只调 £25 解决结构问题 |
| unit_cost / annual_holding_rate | 实际采购成本；资金、仓储、损耗/淘汰等年成本组成，避免重复计费 | 当前 c 为售价比例模拟，h 为演示假设；需一致的时间/货币单位 |
| max_order_coverage_days 与 overstock.coverage_days | 仓储、现金、补货频率、MOQ/包装、保质期、供应能力等约束；分别定义订货上限与超储阈值 | 两个 180 天含义不同，不能为了减少风险标签同时移动两者而不说明 |
| supplier_lead_time_days | 供应商订单至到货记录、分布、异常情况及统计窗口 | 不只调平均数；现代码每 SKU 哈希选一个交期，不等于已建真实随机交期服务模型 |
| service levels / demand | 服务目标定义、真实需求与缺货造成的销量截断、估计周期和销售结构变化 | 模拟月销量代理不能直接证明实际履约概率 |

**当前处理**：保留所有现值，标为演示/待校准，先完善参数登记与来源，不虚构“经业务验证”。不能依据本次最高/最低模拟资金值选择参数；库存生成公式本身也在跟随政策变化。

**验收**：每个拟替换参数有事件单位、数据来源、时间窗口、估计方法、业务负责人及批准记录；供应商合单结构明确。用未参与校准的数据/时间窗口检验服务、缺口与资金指标，在写回正式参数前审阅 A/B 对比。若无真实数据，验收结果只能是“演示参数登记完整”，不能是“模型已校准”。

## 8. 条件研究：B2，短窗口不确定性（不自动重开 D1）

只有用户明确希望重新评估短窗口策略，才进入此项。候选研究包括：保持现规则并显示样本不确定性；与同类较长历史做分层估计/收缩；经业务定义的安全库存约束。这里只列选项，不给出任意系数或推荐阈值。

**取舍**：保留现规则可维护兼容性，但不能解决估计不确定性；保守化可能增加资金占用和超储，未必改善服务；同类借用需要合理分组和足够数据。三月样本“不算 short_history”不代表可以忽视它，也不证明边界应立即改为四月。

**验收**：明确哪些 SKU/窗口适用、哪些既有规则需要更改；采用不泄漏未来的滚动时间切分，给出与现规则相比的偏差/区间、短缺规模和资金权衡，且区分真实需求验证与模拟政策验证。低 CV 或 Normal 标签不能充当成功标准。无真实库存/需求证据时只能产出研究结论，不承诺实际服务改善。
